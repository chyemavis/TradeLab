Practice Portfolio: app map

A practice trading app with pretend money for investing beginners. Confusing terms are explained with plain English and a short animation, and two games teach risk and diversification.

Snapshot of the code at commit 0ca1dbc plus this map. The code can change later; search anchors still work after line numbers move.

The main pieces

Screens and tabssrc/App.jsx switches between Home, Explore, Games, Learn and a stock page, and opens the sheets.
Portfolio rulessrc/state/portfolio.js: buy, sell, top up, badges, and trade explanations. Plain functions, no UI.
Saved datasrc/state/PortfolioContext.jsx keeps your cash, shares, and opened terms in the browser's localStorage.
Simulated pricessrc/state/usePrices.js nudges sample prices every 3 seconds. Not real market data.
Term explanations (the core idea)src/data/terms.js holds the text; src/animations/ holds one animation per term.
Gamessrc/games/sim.js holds the game rules; RiskReward.jsx, Diversify.jsx, and the landscape GameStage.jsx handle the screens.

One action, end to end: tapping "P/E ratio"

The route reference route

Not toured live in the wrap-up; use it next time you want to find your way around. Search for the anchor text in your editor (Ctrl+Shift+F).

  1. src/components/TermLink.jsx, anchor export default function TermLink

    The underlined word with ⓘ. All it does is call onOpen(id) with the term's id, such as peRatio.

  2. src/App.jsx, anchor const openTerm

    Opens the sheet and records the term as opened. That record feeds the ✓ marks on the Learn tab and the "Word nerd" badge.

  3. src/components/TermSheet.jsx, anchor export const ANIMATIONS

    Looks up the text in src/data/terms.js and the matching animation component, then shows both. "Play again" re-runs the animation by changing its key.

A practice to reuse

Give the agent a concrete visual reference, and keep design decisions in tokens.

In this build, descriptive words ("minimal and dark", "more playful") produced looks that were judged too basic or generic. A written brief got closer. A reference screenshot of a real brokerage app produced the look that was approved with a single tweak (mint green to mint blue). The record is under ## Revisions in devpost/checklist.md and in spec.md › Look and Feel.

Because every color lives as a CSS variable in src/index.css, each of those four restyles touched about ten token lines instead of every screen. In the wrap-up, changing --accent recolored the tab bar, pills, and term underlines at once.

Next project: before asking an agent for UI, collect one or two screenshots you like and say what to copy from them (and what not to). Ask for colors and fonts to be defined once as tokens, so later changes are a few lines.

Run it again

npm install      # first time only
npm run dev      # then open http://localhost:5173
On your phone (same Wi-Fi) 
npx vite --host  # then open http://<your-laptop-IP>:5173 on the phone

Find the laptop's IP with ipconfig (look for the Wi-Fi "IPv4 Address"). Allow Node.js through Windows Firewall if asked.

Check the rules without the browser

The trading and game rules are plain functions in src/state/portfolio.js and src/games/sim.js, so you can import them in a small node script and check results directly. That's how they were verified during the build.
